# qB 115 秒传整理联动

适用于 MoviePilot V2 的 qBittorrent 下载完成秒传与自动整理统一插件，融合了 `dxmsk/qb-auto-organizer` 的核心整理流程。

## 功能

- 检测 qBittorrent 已完成任务，并通过本地秒传目录限制处理范围。
- 只处理 qB 新进入“已完成”状态的种子，不会每轮重复读取历史完成种子的文件列表。
- 使用配置的 qB Web API 地址、用户名和密码建立持久登录会话；秒传与整理共享同一个完成任务监控，轮询间隔可按秒配置。
- 可设置本地秒传目录；留空自动使用 MoviePilot 优先级最高的本地下载目录。
- 只读计算文件 SHA1 和 115 二次验证所需的范围 SHA1。
- 仅调用 115 秒传初始化；未命中秒传时不会执行普通上传。
- 网络、Cookie 或协议错误按配置间隔持续重试。
- 首次秒传失败后立即加入 MoviePilot 整理队列；不会由第二个插件重复扫描 qB。
- 后续秒传重试成功时主动移除对应整理任务，并用整理拦截器处理并发边界。
- MoviePilot 整理成功或失败后，停止对应秒传任务。
- 秒传先成功时，在 MoviePilot 真正操作文件前拦截重复整理。
- SQLite 持久化任务及文件状态，插件重启后继续处理。
- 详情页分为“115 秒传”和“自动整理”两个标签页，显示成功时间、大小、来源、目标路径与状态。
- 秒传与整理共用唯一的排除标签；留空处理所有任务，包括带 `已整理`、`刷流` 或其他标签的任务。标签过滤在请求种子文件列表前完成。
- 兼容 qB `Original`、`Subfolder`、`NoSubfolder` 内容布局，并同时使用 `save_path`、`content_path` 和文件快照定位本地文件。

## 要求

- MoviePilot `2.15.0` 或更高版本。
- MoviePilot 已配置并启用 qBittorrent 下载器。
- MoviePilot 容器能够访问 qBittorrent 的完成文件路径。
- 有效的 115 Cookie，至少包含登录所需字段。

## 安装

本压缩包使用标准 MoviePilot V2 插件仓库结构：

```text
package.v2.json
plugins.v2/qb115rapidupload/
```

推荐把解压后的目录推送到自己的 Git 仓库，然后在 MoviePilot“插件市场设置”中添加该仓库地址，刷新市场后安装 **qB 115 秒传**。

本地开发安装可把解压目录配置到 MoviePilot 的 `PLUGIN_LOCAL_REPO_PATHS`，然后刷新本地插件。

## 配置

- **启用插件**：默认开启。
- **qBittorrent 地址/用户名/密码**：直接登录 qB Web API 监听下载完成。
- **监控轮询间隔（秒）**：默认 1 秒，范围 1-3600；秒传和自动整理共同使用。
- **115 Cookie**：必填。
- **秒传目录（本地）**：只处理该目录下的 qB 完成种子；留空使用 MoviePilot 默认本地下载目录，可用逗号分隔多个目录。
- **目标目录 ID**：默认 `0`，即根目录。
- **重试间隔（分钟）**：默认 30，范围 1-1440。
- **整理后停止秒传**：默认开启。
- **秒传成功后取消整理任务**：默认开启。
- **启用自动整理联动**：默认开启；首次秒传失败后进入 MoviePilot 整理队列。
- **排除 qB 标签**：默认留空；命中任一标签时两条处理链都跳过，留空时所有标签均参与处理。
- **强制整理**：按需向 MoviePilot 传递 `manual=true`、`force=true`。

## 安全说明

插件的业务代码不会对下载目录执行写入、移动、重命名或删除。秒传失败也不会回退为普通文件上传。

联动插件会调用 MoviePilot 的 `remove_from_queue` 清理待整理视图，并通过 `TransferIntercept` 在文件操作前阻止已经被工作线程取出的任务。MoviePilot 的整理历史可能显示一次带“115 秒传已成功”的失败/取消原因，这是预期行为。

从 `0.1.x/0.2.x` 升级到 `0.3.x` 时，插件会取消旧版全量扫描自动生成的未完成积压任务，已经成功的记录会保留，并建立 qB 完成哈希基线。升级后只监控基线之外新进入完成状态的 qB 任务；MoviePilot 在下载开始时发送的任务会继续被持久化跟踪。

本版本已经把自动整理逻辑合并到同一个插件和同一个 SQLite 状态机中。请停用或卸载单独的 `QbAutoOrganizer`，避免旧插件继续独立轮询并抢先整理。统一流程固定为“完成检测 → 首次秒传 → 失败后整理入队 → 秒传重试/整理事件竞争收敛”。

115 秒传接口并非稳定公开接口，本插件固定依赖 `p115client==0.0.9.6.4`。如果 115 调整协议，任务会保留并进入重试状态，不会改动本地文件。

从旧版本升级时，如果任务曾因路径拼接错误被标记为“原文件不存在”，插件启动会在确认 MoviePilot 没有对应整理历史、且候选路径实际存在时自动恢复该任务；已经整理过的任务不会被恢复。
